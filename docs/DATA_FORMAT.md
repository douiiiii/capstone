# 데이터 형식 명세 (Data Format)

> 2번 팀원(DB·백엔드 인프라) 과 합의된 데이터 형식 명세.
> 이 문서는 **Supabase(PostgreSQL) 스키마 및 API 직렬화 형식의 단일 출처**.

- 모든 테이블은 SQLAlchemy 모델로 정의되며 `app/models/*.py` 에서 확인 가능.
- 본 문서와 코드가 어긋날 경우, 코드를 정답으로 보되 본 문서의 사유와 함께 갱신할 것.

---

## 1. 권역명 정의 (5개 권역)

매칭 알고리즘의 권역 점수(40점) 계산 기준.
**정확한 한글 표기**가 중요 (공백/철자 불일치 시 0점 처리됨).

| 권역명 | 세부 지역 | 중심 좌표 (lat, lng) |
|--------|----------|-------------------|
| `동부권` | 동탄1, 동탄2 | 37.20, 127.07 |
| `서부권` | 향남, 팔탄 | 37.07, 126.82 |
| `북부권` | 봉담, 기안 | 37.22, 126.92 |
| `남부권` | 우정, 장안 | 37.00, 126.83 |
| `중부권` | 화성시청 | 37.20, 126.83 |

### 인접 관계

```
       북부권
        │
서부권 ─ 중부권 ─ 동부권
        │
       남부권
```

```python
ADJACENT_REGIONS = {
    '동부권': ['중부권', '남부권'],
    '서부권': ['중부권', '북부권'],
    '북부권': ['중부권', '서부권'],
    '남부권': ['중부권', '동부권'],
    '중부권': ['동부권', '서부권', '북부권', '남부권'],
}
```

### 권역명 정규화 (v4.8 도입)

`normalize_region()` — 외부에서 세부 지역명이 들어와도 자동 매핑:

| 입력 | 정규화 결과 |
|------|----------|
| `'동부권'` | `'동부권'` |
| `'동탄1'` | `'동부권'` |
| `'동탄'` (prefix) | `'동부권'` |
| `'향남'` | `'서부권'` |
| `'알수없는지역'` | `'알수없는지역'` (원본 그대로 — 후속 단계에서 0점) |
| `None` 또는 `''` | `None` |

## 2. JSONB 배열 형식

PostgreSQL `JSONB` 컬럼은 항상 **배열 of 문자열** 형태.
빈 배열은 `[]`, 미지정은 `NULL`.

### 강사(Instructor) JSONB 컬럼

| 컬럼 | 값 예시 | 비고 |
|------|--------|------|
| `travel_range` | `["중부권", "남부권"]` | 이동 가능 권역 |
| `specialties` | `["AI기초", "챗GPT", "데이터분석"]` | 전문 분야 |
| `available_days` | `["월", "화", "수"]` 또는 `["평일"]` 또는 `["주말"]` | 평일/주말 카테고리도 OK |
| `available_times` | `["오전", "오후"]` | 카테고리 — 아래 §4 참조 |
| `target_audience` | `["시니어", "성인", "청소년"]` | 교육 가능 대상 |
| `preferred_org_types` | `["복지관", "도서관"]` | 선호 기관 유형 |
| `disliked_org_types` | `["기업"]` | 비선호 기관 유형 |

### 교육요청(EducationRequest) JSONB 컬럼

| 컬럼 | 값 예시 |
|------|--------|
| `preferred_dates` | `["2026-06-01"]` 또는 `["2026-06-01 ~ 2026-06-30"]` |
| `preferred_times` | `["오전"]` |
| `failure_reasons` | `[{"code": "no_region", "message": "..."}]` |

> ⚠️ `preferred_dates` 는 ISO 8601(`YYYY-MM-DD`) 문자열 배열.
> 범위는 `~` 로 구분 (양 끝점만 사용).

## 3. cert_level (강사 인증 등급) 정수 매핑

**v4.8 부터 모든 cert_level 은 정수**. 문자열(`'기초'`) 사용 금지.

| 정수 | 등급명 | 강의 가능 분야 |
|------|--------|--------------|
| `1` | 기초 | AI기초, 스마트폰활용 |
| `2` | 중급 | + 챗GPT, 데이터분석, 코딩교육 |
| `3` | 전문가 | 제한 없음 (모든 분야) |
| `NULL` | 미지정 | 제한 없음 (전문가로 간주) |

### 자동 승급 기준 (`GRADE_UPGRADE_RULES`)

| 현재 | 다음 | 조건 |
|------|------|------|
| `1` (기초) | `2` (중급) | 누적 강의 ≥ 20 + 평균 평점 ≥ 4.0 |
| `2` (중급) | `3` (전문가) | 누적 강의 ≥ 60 + 평균 평점 ≥ 4.5 |
| `3` (전문가) | — | 최고 등급 |

### 화면 표시용 매핑

```python
GRADE_NAMES = {1: '기초', 2: '중급', 3: '전문가'}
```

> ⚠️ `cert_level` 은 일반 API 응답(`/api/instructors`)에서는 제외됨.
> 관리자 API(`/api/admin/instructors`)에서만 노출.

## 4. 시간대 카테고리 (preferred_times / available_times)

`session_time` (카테고리) 와 `session_start_time` / `session_end_time` (시·분 정밀) 두 가지 표현 공존.

### 4.1 카테고리 → 시·분 범위 매핑

| 카테고리 | 시작 | 종료 |
|---------|------|------|
| `오전` | 09:00 | 12:00 |
| `오후` | 13:00 | 17:00 |
| `저녁` | 18:00 | 21:00 |

> 외부에서 구체 시간을 받지 못한 경우 위 범위로 fallback.

### 4.2 충돌 검사 정책 (v4.8)

| 후보 측 | 기존 세션 측 | 비교 방식 |
|--------|------------|---------|
| 시·분 있음 | 시·분 있음 | 구간 겹침 정밀 비교 |
| 시·분 없음 | 시·분 없음 | 카테고리 동일 비교 |
| 한쪽만 있음 | — | 카테고리 fallback |

## 5. status 값 정의

### 5.1 `education_requests.status`
**DB CHECK 제약: `{'대기', '매칭중', '완료'}`**

| 값 | 의미 |
|---|------|
| `대기` | 신규 요청, 아직 매칭 안 됨 |
| `매칭중` | (현재 미사용 — 호환용) |
| `완료` | `POST /api/match` 실행됨 (1건이라도 결과 있음) |

### 5.2 `matches.status`
**DB CHECK 제약: `{'매칭제안', '수락', '거절', '최종확정'}`**

| 값 | 의미 |
|---|------|
| `매칭제안` | 알고리즘이 추천한 상태 (초기값) |
| `수락` | 수요처 수락 (`POST /api/match/<id>/accept`) |
| `거절` | 수요처 거절 또는 30일 자동 만료 |
| `최종확정` | 수요처가 최종 선택 (`POST /api/match/select`) |

> 이전 표기 `'확정'` / `'완료'` 는 **사용 금지**. `'최종확정'` 으로 통일됨.

### 5.3 `matches.match_type`

| 값 | 의미 |
|---|------|
| `정상` | 일반 매칭 |
| `조건완화추천` | 유사 분야로 확장된 매칭 |
| `최선추천` | 평점 기준 fallback 매칭 |
| `신규강사보장` | E 항 신규 강사 보장 슬롯 |

### 5.4 `class_sessions.status`

| 값 | 의미 |
|---|------|
| `예정` | 강의 예정 (활성) |
| `완료` | 강의 진행 완료 |
| `취소` | 매칭 거절/취소로 인한 세션 취소 |

> `count_sessions_in_month()` 와 `has_schedule_conflict()` 는
> `('예정', '완료')` 만 활성으로 간주.

## 6. 매칭 점수 계산 방식

### 6.1 기본 점수 (100점 만점)

| 항목 | 만점 | 조건 |
|------|------|------|
| **권역 점수** | 40 | 일치 40 / 인접 20 / 이동가능 10 |
| **전문분야 점수** | 40 | 완전 일치 40 / 유사 분야 20 |
| **시간대 점수** | 20 | 완전 일치 20 / 부분 일치 10 |
| **기본 합계** | 100 | — |

### 6.2 보너스 / 패널티 (누적식, 100점 초과 가능)

| 항목 | 점수 | 트리거 |
|------|------|-------|
| 평점 보너스 | +10 / +5 / 0 | 평점 ≥4.8 / ≥4.5 / 그 외 |
| 활동일 패널티 | -10 / -5 / 0 | 마지막 활동 >6개월 / >3개월 / 그 외 |
| 만족도 보너스 | +10 | 평균 만족도 ≥4.5 |
| 만족도 패널티 | -10 | 평균 만족도 <3.0 |
| 재요청 보너스 | +15 / +7 | 같은 기관 3회+ / 1~2회 |
| 누적 나쁜평가 패널티 | -30 | 평가 <3.0 가 3회 이상 누적 |
| 기관 유형 보너스 | +10 | 학교(누적 30회+) / 기업(전문가) / 복지관(시니어) |
| 과거 매칭 이력 보너스 | +5 | 같은 기관 이전 매칭 1회 이상 |
| 월 강의 80% 패널티 | -15 | 이번 달 매칭 ≥80% |
| 매칭 쏠림 패널티 | -10 | 이번 달 최다 매칭 강사 |
| 정기 강의 보너스 | +10 | 정기 요청 + 월 가능 횟수 ≥3 |
| 신규 강사 보너스 | +20 | 누적 강의 <10회 |
| **상성 보너스** | +15 | 해당 기관 유형 평균 만족도 ≥4.5 |
| 선호 기관 보너스 | +10 | 강사 `preferred_org_types` 일치 |
| 비선호 기관 패널티 | -5 | 강사 `disliked_org_types` 일치 |
| 성장 강사 보너스 | +10 | 다음 등급 80% 진척 |
| **권역 부적합 가드** | **-20** | 권역 점수 0점일 때 자동 적용 |

### 6.3 자동 제외 (점수 계산 전 필터링)

| 조건 | 효과 |
|------|------|
| `is_active=False` | 후보에서 완전 제외 |
| 이번 달 매칭 ≥ `max_classes_month` | 자동 제외 |
| 정기 강의 일정 충돌 | 자동 제외 |
| 요일 불일치 (`available_days`) | 자동 제외 |
| 인증 등급 부적합 (`cert_level`) | 후보 풀에서 제외 |

### 6.4 동점자 정렬 기준

1. 총점 내림차순
2. 평점 내림차순
3. 누적 강의 횟수 내림차순

## 7. 더미 데이터 시드 정책

`app/services/seed_data.py` 는 **빈 DB 일 때만** 시드 데이터 삽입.
대량 데모 데이터는 `scripts/seed_demo_data.py` 로 별도 실행.

| 스크립트 | 규모 | 사용 시점 |
|---------|------|---------|
| `seed_data.py` (자동) | 강사 ~6명 / 기관 ~3곳 | 첫 실행 시 자동 |
| `seed_demo_data.py` (수동) | 강사 40+명 / 기관 30+곳 / 요청 60+건 | 시연 데이터 풍부화 |

## 9. ML 학습 로그 (MLTrainingLog) 형식

```json
{
  "id": 1234,
  "request_id": 1,
  "instructor_id": 7,
  "was_selected": true,
  "was_conducted": true,
  "final_satisfaction": 4.5,
  "not_selected_reason": null,
  "match_score": 115.0,
  "engine_version": "rule_based_v4",
  "feature_snapshot": {
    "request": { "specialty": "AI기초", "...": "..." },
    "instructor": { "region": "동부권", "...": "..." }
  },
  "created_at": "2026-05-27T15:00:00",
  "updated_at": "2026-05-27T18:30:00"
}
```

라이프사이클:
1. `find_top_matches()` 호출 시 추천 후보 N명 각각 행 생성 (`was_selected=False`)
2. `POST /api/match/select` 시 선택된 강사 → `was_selected=True`, 나머지 → `not_selected_reason` 기록
3. `POST /api/match/feedback` 시 `was_conducted` + `final_satisfaction` 갱신

**완전 라벨**(학습 가능) 조건: 위 3개 필드가 모두 채워진 상태.
